How to contribute

Contributions are most useful when they solve an agreed problem and can be verified by someone else.

  1. Pick a user problem. Read the area guide and look for an existing issue before starting.
  2. Agree on the outcome. Open an issue with the target user, proposed behavior, supported environment, and a small definition of done.
  3. Build and verify. Keep the change focused; include tests for executable behavior and check commands in a clean environment.
  4. Document honestly. Update setup, versions, limitations, and safety notes. Clearly distinguish implemented features from proposals.
  5. Open a pull request. Explain the problem, change, and verification performed. See the full contribution guide.

Safe by default

Developer tooling should make important network and credential boundaries clear.

Use local development or Stellar testnet for examples.

Never commit secret keys, seed phrases, or credentials. Make network actions explicit, explain transaction costs and permissions, and do not describe tests as a security audit or an unaudited example as production-ready. See the deployment safety requirements.

Get started

The repository itself is documentation-only and has no install step. A contribution may have its own requirements; state them in that feature's guide.

Clone the repository and read the contribution guide. Install Rust or the Stellar CLI only when needed for the feature you are working on.
